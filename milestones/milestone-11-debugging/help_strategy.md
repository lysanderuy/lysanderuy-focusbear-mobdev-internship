# Onboarding Task - When you get stuck - what next

## Decision Making framework

I created a troubleshooting decision framework that starts with three checks: information sensitivity, urgency, and
problem complexity.

- If the issue is sensitive, I first use internal documentation and then ask a colleague if needed.
- If the issue is urgent, I spend 10-15 minutes investigating before escalating to a teammate.
- For non-urgent issues, I use Google/Stack Overflow for low complexity, AI plus documentation checks for medium
  complexity, and debugging tools with senior support for high complexity.

## Reflections

### When do you prefer using AI vs. searching Google

I use AI first when I need a fast explanation, a starting point, or help breaking a problem into smaller steps.
I switch to Google when I need official documentation, version-specific behavior, or confirmation from real-world
discussions. In practice, I combine both: AI for direction, Google for verification.

### How do you decide when to ask a colleague instead

I ask a colleague when the issue is blocking progress for too long and I have already tried the obvious checks
myself. I also ask earlier when the code area is team-owned, high-risk, or tied to project decisions I should not guess
on. Before asking, I share what I tested so they can help quickly without repeating basic steps.

### What challenges do developers face when troubleshooting alone

The biggest challenge is tunnel vision, where I can spend too long on one assumption and miss simpler causes.
It is also easy to lose time jumping between tools without a clear plan or stopping point. Working alone can add stress
and self-doubt, especially when bugs are intermittent and hard to reproduce.
